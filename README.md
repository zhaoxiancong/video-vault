# 视频下载工具 · Video Vault

一个跑在你自己电脑上的**视频下载 + 个人视频库**工具。粘链接进去，它负责下载、归类、入库；
下载完的片子能搜索、能筛选、能直接在网页里播放，还能一键转成剪辑软件好用的格式。

- **零运行时依赖** —— 只用 Node 内置模块（`node:http` / `node:sqlite`），没有 `node_modules`
- **前端无构建步骤** —— 原生 ES 模块，改完刷新就生效
- **引擎**：yt-dlp（1800+ 站点）+ ffmpeg（合并音视频流）

---

## 1. 怎么用（三步）

1. 双击 **`启动.cmd`**（首次运行会自动下载引擎，约 344MB，只需一次）
2. 浏览器会自动打开 `http://127.0.0.1:8787`
3. 在「添加下载」页把视频链接粘进去 → 点「加入下载队列」

关掉那个黑色命令行窗口 = 停止工具。**没下完的任务不会丢**，下次打开点「全部继续」接着下。

> 不想用 bat，也可以命令行（先 `cd` 到你放这个项目的目录）：
> ```powershell
> .\启动.ps1                 # 默认 8787 端口
> .\启动.ps1 -Port 8899      # 换端口
> ```
>
> 两个启动脚本做的事一样：前台运行服务，**由服务自己打开浏览器**。
> 想自己起服务、不要浏览器，直接：
> ```powershell
> node src\main.js           # 不带 --open 就不会开浏览器
> ```

> ⚠️ **改这两个启动脚本时注意**（都是实测踩出来的，详见第 6 节）：
> `启动.cmd` 里**一个字中文都不能有**（cmd 会把它们当命令执行、服务起不来），
> `启动.ps1` **必须带 UTF-8 BOM**，两个都要 **CRLF 行尾**。
> 改完跑一次 `node tools\fix-launchers.js` —— 编辑器写出来的形态是错的，
> 而且"看着没问题、双击就坏"。`npm run check` 里也有检查盯着。

## 2. 你的三个真实需求，分别落在哪

被 grill 出来的原话是：**建自己的学习资料库**、**存下来防丢**、**当剪辑素材用**。
这三个需求其实**互相冲突**——防丢要"原始文件别动它"，剪素材要"统一格式方便剪"。
工具是按这个冲突设计的：

| 需求 | 实现方式 | 在哪看 |
|---|---|---|
| **防丢** | 原始文件**只写一次、永不改动**；重名不覆盖；带 URL 去重，同一个片子不会重复下 | 下载目录里的原始文件 |
| **建库** | 每条下载写进 SQLite：标题/作者/站点/时长/分辨率/编码/简介/封面，支持关键词搜索 + 站点/作者/状态筛选 + 收藏 + 备注 | 「我的库」页 |
| **找片** | 粘一个网页地址（列表页/频道页），从中找出视频链接，按关键字筛完再勾选入队 | 「找视频」页 |

> **关于「当剪辑素材用」**：早期版本为此做过一套转码功能
> （5 个预设、产物另存 `_converted/`）。**后来用户明确说用不到，已整体移除** ——
> 现在库里只有原始文件，没有任何转码入口。
> 若将来又需要，那套设计的取舍记录在本文第 6 节（坑 19）里，可以照着重新实现。

也就是说：**原始文件 / 数据库检索两层分开**，互不干扰。
你删了库记录，也能选择保留磁盘上的文件。

## 3. 功能一览

### 下载
- **批量粘链接**：一行一个，可一次丢几十条；自动去重
- **通用站点**：交给 yt-dlp 的 1800+ extractor，不挑站
- **播放列表 / 合集 / 频道自动展开**：喂一个列表地址，自动拆成一堆单集排队
- **清晰度**：最高可用 / 4K / 2K / 1080p / 720p / 480p / 360p / 最小体积
- **仅音频**：抽成 MP3
- **并发 2**（可调）：模拟一个人正常看片的节奏，降低被风控的概率。限速默认关闭，想降风险再开
- **实时进度**：进度条 + 速度 + 剩余时间 + 当前阶段（下载中 / 合并中 / 抽音频中）
- **可展开的原始日志**：出问题时能直接看到 yt-dlp 说了什么
- **暂停 / 继续 / 取消 / 重试 / 删除**

### 登录态（Cookie）
有些站点不登录就下不动：**抖音**即使不登录也强制要求带 Cookie，**B 站**的 1080P+、
番剧和会员内容需要登录态。在「设置 → 登录态」里配一次，之后所有下载自动带上。

两种来源：读浏览器（`--cookies-from-browser`）或自己导出的 `cookies.txt`（优先级更高）。
设置页有「测试登录态是否可用」按钮 —— 它**真的**拿一个需要登录态的地址跑一次解析，
而不是只告诉你"已配置"。

**隐私**：默认不读任何 Cookie，必须显式开启。Cookie 内容不写日志、不入库、不回显。

### 从网站找视频

粘一个**网页地址**（列表页、频道页、站点首页都行），它会找出页面上的视频链接，
你用关键字筛出想要的，勾选后批量加入下载队列。

- **双路径**：先试 yt-dlp（有解析器的站直接拿到标题、时长、真链接），
  不行再解析静态 HTML（从链接的 slug/`title` 属性取标题、从页面取时长角标）。
  界面会显示**走了哪条路** —— 没缩略图时你才知道为什么。
- **关键字筛选是本地过滤**：空格分词 = AND，`-词` = 排除。敲字即时响应，不重新请求。
- **候选持久化**：关掉浏览器明天回来还能接着挑，也可以在多页结果之间来回跳。
- **已在库标记**：爬到的条目会标出"已在库 / ＋新 / 已加入队列"，不会重复下。
- **翻页不自动**：页面上的翻页链接会列出来，点哪一页就用那个地址再抓一次，
  **不替换当前结果**（所以第 1 页和第 2 页的候选都在）。
- 单次最多 200 条，**不会自动翻页凑满**。

#### 爬取纪律（设计约束，不是可调参数）

| 约束 | 值 |
|---|---|
| 单次爬取的页面请求数 | **1**（点翻页 = 新一次） |
| 超时 | 15 秒 |
| 响应体上限 | 3MB |
| 并发 | 串行（一次只跑一个爬取） |
| 单次条数上限 | 200 |
| User-Agent | 真实浏览器 UA |
| 跟随页面内链接 | **否**（不整站爬） |
| robots.txt | 发请求前检查一次并缓存；`Disallow` 命中则**不抓**并说明原因；`Allow`/`Disallow` 冲突取匹配更长的那条 |

**不做的事**：不绕过 Cloudflare 之类的反爬（遇到就明确报错）；不用真浏览器渲染
JavaScript 页面（服务端抓到的 HTML 里没有链接时会明说"这种站暂不支持"）；
不做定时自动抓取。

> 慢站超过 20 秒会自动转后台继续抓，界面显示进度；**关掉浏览器也不影响它抓完**，
> 结果照样入库。

### 页面状态会记住
- **最近任务**面板：列出已完成/失败/暂停/取消的任务，每条都能播放、重新下载、看日志、删除
- 你填的东西持久化在 localStorage：粘贴框内容、清晰度、限速、库页的筛选条件等
- 刷新后队列里正在跑的任务会重新出现并继续显示进度（服务端在跑，不是前端在跑）

### 删除的两种模式（都不会误删）

| 选项 | 结果 |
|---|---|
| **1｜只从列表删掉（默认）** | 记录消失，**磁盘上的视频文件保留** |
| 2｜记录和文件一起永久删除 | 会再确认一次，确认后才删文件 |

> 默认值是"保留文件"，所以**直接回车不会毁数据**。
> 「最近任务」面板上的「清空已完成记录」同理：**只清列表，不动文件**。

### 库
- 缩略图网格 / 列表两种视图
- 关键词搜索（标题、作者、简介、链接）
- 按 状态 / 站点 / 作者 筛选，按 加入时间 / 标题 / 体积 / 时长 排序，仅看收藏
- **网页内直接播放**（支持拖动进度条 —— 服务端实现了 HTTP Range）
- 收藏、备注、复制文件路径、删除记录（可选是否连文件一起删）

## 4. 代码结构

重构过一轮，现在是**四层**，依赖方向单向朝内：

```
src/
├── main.js                 组合根：建立依赖 → 起服务。全项目唯一知道所有模块的地方
│
├── domain/                 领域层（纯逻辑，不碰 IO、不碰数据库）
│   ├── video.js            Video 模型、URL 归一化、元数据归一化、字段白名单
│   ├── job-state.js        任务状态机（哪些状态转换合法，只有这一处定义）
│   └── errors.js           错误分类：把引擎的英文报错翻译成"你该做什么"
│
├── infra/                  基础设施层（唯一碰外部世界的地方）
│   ├── config.js           路径与默认设置；**加载无副作用**
│   ├── database.js         SQLite 仓储；**不导出裸连接**，SQL 全关在这一层
│   ├── subprocess.js       子进程执行；**唯一 spawn 的地方**（fd 重定向，不用管道）
│   ├── progress.js         yt-dlp 输出解析（进度帧、错误清洗）
│   ├── media.js            ffprobe 探测、文件完整性校验、目录清理
│   └── urldiag.js          "这个地址是什么"诊断
│
├── app/                    应用服务层
│   ├── downloader.js       引擎适配：怎么调 yt-dlp 只在这一层
│   ├── scheduler.js        队列调度 + 单任务生命周期

│   ├── cookies.js          登录态
│   ├── crawl-parse.js      抓取结果解析（纯函数、无 IO、最容易测）
│   ├── crawler.js          双路径抓取：yt-dlp 优先，退到静态 HTML；含 robots 检查
│   └── discovery.js        爬取任务生命周期：串行、20 秒兜底转后台、事件广播
│
├── http/                   HTTP 层（只做"校验参数 → 调服务 → 返回视图"）
│   ├── server.js           路由分发 + 错误翻译 + 优雅关闭
│   ├── router.js           路由表 + JSON 响应 + 请求体读取
│   ├── validate.js         参数校验（声明式 schema）
│   ├── static-and-sse.js   静态资源 + 服务端推送
│   ├── views.js            出站数据形状（哪些字段能给浏览器看）
│   └── routes/             videos / library / settings / discover
│
└── web/                    前端（原生 ES 模块，无构建步骤）
    ├── index.html
    ├── app.js              入口，只做接线
    ├── api.js              所有网络请求的唯一出口
    ├── dom.js              DOM 构造与格式化（el() 保证不拼 innerHTML）
    ├── state.js            全局状态 + localStorage 持久化
    ├── ui.js               toast 与确认框
    └── views/              add / discover / queue / library / settings / player
```

### 为什么这么分

**依赖方向单向**：`http → app → domain`，`app → infra`，`domain` 不依赖任何东西。
所以领域逻辑可以在没有数据库、没有网络的情况下测试。

**依赖注入而不是模块单例**。所有服务通过工厂函数接收依赖：

```js
const app = createApp({ data: '/tmp/x', downloads: '/tmp/y' });
// 或者只拿一部分：
const repo = createDatabase(config);
const scheduler = createScheduler(config, { repo, downloader, media, settings });
```

好处很直接：**测试可以起一个完全隔离的实例**，不碰用户数据。
重构前做不到 —— `require('./lib/db')` 一执行就打开了真实数据库，
测试只能操作用户的真实数据（历史上因此误删过 7 条记录）。

**加载模块没有副作用**。`config.js` 不再在 require 时建目录，
`database.js` 不再在 require 时开库。要建目录就显式 `ensureDirs(config)`，
要开库就显式 `createDatabase(config)`。

### 目录

```
20260920_视频下载工具/
├── 启动.cmd / 启动.ps1      ← 双击这个
├── src/                     ← 程序本体
├── test/                    ← 测试（219 项）
├── tools/                   ← 辅助脚本（引擎安装、重建库、静态检查）
├── downloads/               ← 视频都在这（可在设置里改）

├── data/
│   ├── vault.db             ← 视频库数据库（SQLite）
│   ├── thumbs/              ← 封面缩略图
│   └── logs/                ← 每个任务的完整原始日志
└── tools/bin/               ← 引擎（yt-dlp / ffmpeg），首次运行自动下载
```

命名规则：`站点\作者\标题 [高度p格式号].扩展名`。

### 这个文件夹可以随便搬

整个目录**复制或移动到任何位置都能直接用**（换盘、换电脑、放 U 盘都行）：
启动脚本用 `%~dp0` 定位、程序内部路径全部从 `__dirname` 推导，
数据库里存的绝对路径**启动时会自动修正**到新位置。

> 自愈只认 `downloads\` 和 `data\` 这两个**本项目自己的**子目录作为锚点，
> 所以如果你把下载目录改成了外部路径（比如 `D:\Media\`），它不会被误改。

**所有测试都在临时目录里跑**，不碰你的真实库。这是重构带来的直接好处。

> ### 刚 clone 下来没有引擎，测试会「跳过」而不是「失败」
>
> `tools/bin/` 下的引擎（约 344MB）**不进 git**，要靠 `npm run setup` 下载。
> 所以还没装引擎时，有 12 项测试会被标记为**跳过**，并在跳过原因里写明怎么办：
>
> ```
>   ✔ test/unit/media.test.js               13 通过 2 跳过
>       ﹣ isPlayable 对垃圾内容返回 false（要真 ffprobe 才作数）
>         # ffprobe 没装（找不到 ...\tools\bin\ffprobe.exe）—— 先跑 `npm run setup` 下载引擎
> ```
>
> **为什么是"跳过"而不是"通过"**：这些项要真有引擎才有意义。以前的写法是
> 提前 `return`，汇总里显示**通过** —— 一条断言都没跑，却和"真测过了"长得一样，
> 整片需要引擎的测试会在没引擎的机器上集体假绿。环境导致的"没测"和真正的"测过了"
> 必须长得不一样，这是这个项目吃过的一次亏（见坑 19 那一类）。


> `test/e2e/download.test.js` 断言的是完整闭环：下载 → 合并 → ffprobe 入库 →
> 网页播放 Range → 库查询去重 → 中间分片被清理。它默认**会跑**（约 12 秒）；
> 不想走流量就设 `VAULT_SKIP_E2E=1`。

### 前端怎么在没浏览器的情况下测

`test/helpers/dom-shim.mjs` 是一个**刻意保持最小**的 DOM 垫片：
元素树、`querySelector`（含后代组合）、事件冒泡与委托、`classList`、`style`、
`dataset`、`localStorage`，外加假的 `fetch` / `EventSource`。
`test/integration/frontend-dom.test.mjs` 用它把前端**真的 import 进来、真的点几下**。

它挡得住这三类问题（静态检查挡不住，而真实浏览器在受限环境里起不来）：

1. 模块级代码在 import 时抛异常（某个 `#id` 找不到）
2. 事件处理器一跑就崩
3. 渲染出来的节点结构不对、或误用了 `innerHTML`

它**替代不了**真实浏览器：没有布局、没有 CSS 级联、没有渲染、没有 `elementFromPoint`。
那些仍然要靠 `test/ui/smoke.js`（需要放宽权限的会话）。

> 垫片自己踩过的坑都写在注释里了，改它之前值得读一遍 ——
> 最费时间的一类问题是"垫片不够真导致的假失败"：测试红了，被测代码其实是对的。
>
> ⚠️ **最严重的一次**是冒泡链断了：`body._parent` 曾是 `null`，而 document 不在冒泡链上，
> 于是事件走到 body 就停 —— 库页的播放/收藏/更多**全靠 document 上的事件委托**，
> 它们在前端测试里**从来没被触发过**。真实浏览器里 document 在链上，
> 所以这是垫片与真实 DOM 的偏差，它让整整一类交互逃过了测试。
> 现在的链是 `元素 → body → html → document`。

### 没有浏览器时怎么办

`test/ui/smoke.js` 需要真实的 Chrome。受限沙箱里 Chrome 起不来
（crashpad 要 OpenProcess、多进程 IPC 要命名管道），它会**明确跳过**而不是报失败 ——
把它算成失败会训练人忽略这个测试。

跳过时 `tools/check-frontend.js` 仍然会跑，能挡住大部分低级错误：
`#id` 拼错、import 路径写错、把可变文本拼进 `innerHTML`、忘了 `type="module"`。

## 6. 开发时踩过的坑（改代码前必读）

这几条都是**实测撞出来的**，不是推测。改相关代码前先看一眼，能省你几个小时。

> ⚠️ **其中几条讲的代码已经不存在了**：转码功能（`src/app/transcode.js`、
> `startTranscode()`、`_converted/`）已于 2026-09-21 按用户要求**整体移除**。
> 那些条目**刻意保留** —— 它们记的是"这类错误长什么样、为什么会长期没被发现"，
> 换一个功能照样会犯。看的时候把函数名当成历史名词即可。

### 坑 0：启动脚本的字节形态（"双击没反应"就是这个）

用户报过一次"启动脚本不可用"。实测复现出来的症状是：**每一行中文都报**
`<乱码> 不是内部或外部命令`，**服务根本没起来**。

| 文件 | 必须是什么形态 | 为什么 |
|---|---|---|
| `启动.cmd` | **纯 ASCII** + CRLF | `cmd.exe` 用系统 ANSI 代码页解析 .cmd 文件，而 `chcp 65001` 只改变*输出*。多字节 UTF-8 被拆错 → cmd 把中文提示当命令执行 |
| `启动.ps1` | **UTF-8 带 BOM** + CRLF | PS 5.1 读无 BOM 的 UTF-8 会按 GBK 解析 → 中文乱码，严重时语法错误 |

实测：把 `.cmd` 的行尾从 LF 改成 CRLF，脚本**就能起来了**；但每行中文仍报错 ——
两个因素是叠加的。中文提示现在放在 `tools/launcher-banner.js`（Node 读 UTF-8 没问题）。

⚠️ **编辑器写出来的形态是错的**（无 BOM + LF），所以改完启动脚本必须跑一次：

```powershell
node tools\fix-launchers.js     # 规范字节形态并复查
node tools\check-launchers.js   # 只检查（已接进 npm run check）
```

另一条同源的经验：**别把服务放到后台起**。`start /b node src/main.js` 之后，
窗口关掉 node 还在跑，"关闭本窗口即停止工具"就成了假话（实测确实如此）。
现在两个脚本都是**前台运行服务、由服务自己开浏览器**（`--open`）——
零轮询、零后台作业、零孤儿进程，进程生命周期天然绑在窗口上。

---

### 坑 1：子进程输出不能走管道（沙箱限制）

受限环境**禁止 `spawn` + 管道读子进程 stdout**（抛 `EPERM`）。更麻烦的是
**这个限制是会话级、会变的** —— 同一段代码在放宽权限的会话里一切正常，
换个受限会话就全挂。而且它失败的方式很阴：`spawnSync` 抛 EPERM 后如果只读
`r.stdout`，拿到的是空字符串，看起来像"命令没输出"，实际是**命令根本没跑起来**。

所以全项目所有子进程一律走**文件描述符重定向**（`src/infra/subprocess.js` 是
唯一 spawn 的地方）。副作用是好的：每个任务都有完整原始日志，排错很方便。

> 这个坑咬过两次：一次让静态检查报"失败"（其实是子进程起不来），
> 一次让所有下载静默失败（报错是 `trace is not defined`）。

### 坑 2：yt-dlp 单文件版跑不起来

官方 `yt-dlp.exe`（PyInstaller onefile）会在系统 `%TEMP%` 里自解包，受限环境拒绝，
报 `Failed to create parent directory structure`。
**必须用目录式分发包 `yt-dlp_win.zip`**（exe + `_internal` 同级）。
`tools/bootstrap-engine.js` 已经处理了这件事（还会检查 `_internal` 在不在）。

### 坑 3：中文路径会变乱码（最阴的一个）

子进程通过 fd 重定向写文件时，中文 Windows 默认按**系统 ANSI 代码页（GBK）**编码，
于是日志里的路径变成 `...\20260920_??Ƶ????\...`，`fs.existsSync()` 永远失败，
**文件永远收不了尾**。两个修法一起用：

- 给子进程设 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`（见 `childEnv()`）
- 最终文件路径用 `--print-to-file`（yt-dlp 自己以 UTF-8 落盘），**不走 stdout**

### 坑 4：进度模板绝不能交给 yt-dlp 生成结构化格式

这里连撞两次：
1. 用 `%(...)s` 把 `_percent_str` 插进 JSON → 得到 `{"p":  0.5%}`，**不是合法 JSON**
2. 改用 `%(...)j`（JSON 编码）→ 字符串字段好了，但**数值字段取到 `NA` 时仍输出裸 `NA`**
   （`{"frag":NA}`），照样非法

**最终方案：管道分隔纯文本**，服务端自己解析：
```
VVP|  0.5%|1024|223779|68430.4|3|NA|NA      ← 下载进度
VVP|Merger|started                          ← 后期处理
```
`NA` 只是自己那一格的值，永远破坏不了整体结构。

### 坑 5：高清流要合并进 mkv

YouTube 高清普遍是 vp9/av1 + opus，**mp4 容器装不下**，强行 mp4 会让合并直接失败。
所以视频统一合并进 `.mkv`。（想转 mp4 请用别的工具 —— 本工具已移除转码功能。）

### 坑 6：验证语法不要用 `require()`

`node -e "require('./src/main.js')"` 会**真的把服务启动起来**然后卡住。
用 `node --check <file>`。

### 坑 7：`[hidden]` 会被任何 `display` 规则顶掉

浏览器给 `[hidden]` 的默认样式是 `display:none`，但它**优先级低于任何 class 选择器**。
所以只要组件里写了 `display:flex`，`hidden` 属性就完全失效。

当时的后果：`.modal { display:flex }` 让播放弹层的全屏深色遮罩从页面加载起
就一直盖在最上层，用户打开页面后点什么都没反应，看起来像"关闭按钮坏了"。

修法是样式表开头的这一行，**它是整个界面能用的前提**：
```css
[hidden] { display: none !important; }
```

### 坑 8：沙箱里起不了 Chrome，UI 测试要提权

Chrome 的 crashpad 要 `OpenProcess`、多进程 IPC 要命名管道，在受限沙箱里全被拒。
`test/ui/smoke.js` 会识别这种情况并**跳过**（不是失败）。

### 坑 9：进度条整场卡在 99%

**错误假设**："看到后处理器 = 下载已经结束"。
**为什么错**：yt-dlp 的 `ThumbnailsConvertor` 会在**下载开始之前**就先执行一次。
结果进度条从开场就被钉死在 99%，而真实下载从 0.1% 一路走到 99.4%。

**正确做法**：只有 `Merger` / `ExtractAudio` / `VideoConvertor` / `VideoRemuxer` /
`Fixup` 出现在**已经收到过下载进度之后**，才算进入后处理（见 `POST_STAGE_RE`）。

**附带发现**：yt-dlp 的多条流会**各自从 0% 走到 100%**，所以进度条一定会"归零一次"。
这不是 bug，但必须告诉用户，否则看起来就像坏了。

### 坑 10：错误信息里存进去的是一段进度帧

`cleanError()` 原先取"日志最后一行"，而进度帧恰好排在最后，
于是数据库里的 `error` 字段变成 `VVP|100.0%|21039208|...`。

修法：先把 `VVP|` / `VVAULT_` / 进度条 / `Deleting ... file` 这些噪音行全部排除，
再找 `ERROR:` 行；如果只是笼统的 `Postprocessing:`，取它**后面**那行。

### 坑 11："文件存在" ≠ "文件完整"

下载被中断会留下半截分片，yt-dlp 合并时读到坏数据直接报
`Invalid data found when processing input`，但最终文件确实躺在磁盘上。

现在的做法：用 **ffprobe 实测**产物（有时长、视频文件还要有分辨率），
不合格就清掉残留 + **自动重下一次**（只重一次，避免坏源无限循环）。

### 坑 12：抖音网页版复制出来的地址 yt-dlp 不认

`https://www.douyin.com/jingxuan?modal_id=7671972624104197391` 这种地址
yt-dlp 只认 `/video/<id>`。`normalizeUrl()` 会自动转换，界面上也会说明。

### 坑 13：异步调度器写成了同步无限递归（最严重的一个）

**症状**：服务端跑不到 2 分钟就 `FATAL ERROR: Reached heap limit`，
堆涨到 4GB 崩溃。

**根因**：为了加封面判断，`_start()` 改成了 `async`，但把任务状态从 `queued`
改成 `downloading` 的代码**在 await 之后**。await 让出控制权时任务**还是 `queued`**，
此时任何 `kick()` 都会把它再捞起来启动一次 —— **同一毫秒内 `_start` 被调用上千次**。

**三道防线（少一道都不行）**：
1. `kick()` 用 `setImmediate` 异步调度，打断同步递归链
2. `_schedule()` 在调用 `_start()` **之前**就把 id 放进 `running` 占位
3. `_start()` 在**任何 await 之前**完成状态迁移

**教训**：把同步函数改成 `async` 时，状态迁移一定要发生在第一个 `await` 之前。

### 坑 14：删调试代码漏删一处，整个功能静默失效

为了定位内存问题加过 `trace()`，事后删的时候**漏了一处**，
于是 `_start()` 一进 try 就抛 `ReferenceError: trace is not defined`，
被 catch 吞掉后变成"解析失败: trace is not defined" ——
表面看是"解析失败"，实际是**所有新任务全部下载失败**。

同类问题还有一个：`startTranscode()` 用了 `spawn()` 但只导入了 `spawnSync`，
所以**转码功能从来就没能用过**。

`node --check` 只查语法，这两种都抓不到。所以做了 `tools/lint-undefined.js`。

### 坑 15：粘"页面链接"时只报一句 `Unsupported URL`

用户粘的往往是**页面地址**而不是某个视频的地址。yt-dlp 只会回一句
`Unsupported URL: ...`，**用户完全不知道下一步该做什么**。

现在的做法（`src/infra/urldiag.js`）：解析失败时额外抓一下那个页面，
统计里面有多少个"像视频详情页"的链接，据此给出结论。

**边界（刻意设的）**：只在解析失败时才抓、10 秒超时、最多读 512KB、
失败就静默退回原始报错。**不做整站爬虫**。

### 坑 16：insertVideo 的白名单静默丢字段

`db.js` 里"插入"和"更新"原本各维护一份字段白名单，两边会各自漂移。
实际后果：`insertVideo()` 的白名单漏了 `file_path` / `file_size` / `thumbnail_path`，
**传进去的字段被静默丢弃** —— 记录插进来了，但文件路径是 `null`，不报错、不崩溃。

修法是两份名单合成一份 `WRITABLE_COLS`，并加了开发期自检：
`VAULT_STRICT_DB=1` 时，传了不在白名单里的键就直接抛错。

### 坑 17：`save` 覆盖了人工整理的内容（交接工具踩的）

跨会话交接工具最初把「验证命令」「启动方式」也当成"工具生成"的小节，
于是一次 `save` 就把人精心挑的验证命令替换成了自动探测的猜测 ——
**交接质量越用越差，而且完全静默**。

修法：只有「环境事实」「变更文件」是生成节，其余一个字都不动。

### 坑 18：这条是关于"测试替身"的

写集成测试时，**别用"刚添加完还是 queued 状态"这种假设** ——
调度器会立刻把任务捞起来开跑（变成 parsing/downloading/失败）。
那是在跟调度器抢时序，会做出随机失败的测试。

正确做法：明确把记录设成你想测的那个终态，再测目标逻辑。

### 坑 19：转码产物打不开 —— 输出路径被传了两次

**症状**：转码显示成功、`_converted/` 里也真的有文件、大小也正常，
但打不开。ffprobe 说 `Invalid mvhd time scale -1108944568`，streams 为 0。

**根因**：`startTranscode()` 里拼参数时，输出路径出现了两次：

```js
// 错误写法：preset.args(outPath) 的契约就是"以输出路径结尾"
const args = ['-y','-hide_banner','-i', src, ...preset.args(outPath), outPath];
//                                                                  ^^^^^^^ 多余
```

于是 ffmpeg 拿到两个输出、指向同一个文件，写了两遍。日志里能直接看到：

```
Output #1, mp4, to '....mp4'
Output #0, mp4, to '....mp4'      ← 同一个文件
```

mp4 的 moov atom 因此被写坏，产物是个废文件。

**为什么长期没被发现**：老的 `selftest.js` 测转码时是**直接调 ffmpeg、自己拼参数**的，
从来没有走过 `startTranscode()` 这条真实路径。测试跑得再多，
只要它绕过了出问题的代码，就等于没测。

**顺带修的**：`media.probe()` 原来是直接 `JSON.parse(整段 ffprobe 输出)`。
ffprobe 即使加了 `-v error`，也可能在 JSON **前面**吐一行警告
（就是上面那个 `Invalid mvhd time scale`），于是 parse 失败 → `probe` 返回 null →
**一个完全正常的视频被判成"损坏"、删掉、重下**。现在从第一个 `{` 开始截取。

### 坑 20：测试"跳过"写成了"提前 return"，于是一片假绿

**症状**：一台没装 ffmpeg 的机器上跑测试，汇总显示

```
✔ test/integration/media-and-transcode.test.js   9 通过 1 失败
```

**9 个"通过"里，有 7 个一条断言都没跑。**

**根因**：需要引擎的测试是这么写的：

```js
const f = makeSampleVideo(e.tmp);
if (!f) { console.log('  ⏭  ffmpeg 不可用，跳过'); return; }   // ← 测试算"通过"
```

`return` 只是提前结束函数，node:test 依然把它算作**通过**。于是"没测"
和"测过了"在汇总里长得一模一样 —— 比直接失败更危险，因为它不会引起注意。

**后果**：整片转码 + 元数据测试（"当剪辑素材用"这个核心需求的实现路径）
在没有引擎的机器上是**完全空转**的，而报告看起来是绿的。

**改法**：用 node:test 原生跳过，让它在汇总里单独计一栏：

```js
const noFFmpeg = skipWithout('ffmpeg');          // test/helpers/engines.js
test('转码绝不动原始文件', { skip: noFFmpeg }, async (t) => { ... });
```

现在没引擎时是 `2 通过 8 跳过`，并且每条都写明原因和怎么办：

```
﹣ isPlayable 对垃圾内容返回 false（要真 ffprobe 才作数）
  # ffprobe 没装（找不到 tools\bin\ffprobe.exe）—— 先跑 `npm run setup` 下载引擎
```

**顺带修的**：一根"环境导致的失败"也不是真失败。同一次排查里发现
`原始文件不存在时转码被拒绝` 在没 ffmpeg 的机器上必然失败 ——
因为 `start()` 是**先查 ffmpeg、再查源文件**，根本走不到那条分支。
失败原因跟它想测的东西毫无关系，属于**假失败**。这条也归到 `skipWithout('ffmpeg')`。

**一句话**：环境导致的"没测"、和真正的"测过了"，在报告里必须长得不一样。
同类教训还有坑 15（`kill-safe` 的护栏测试把环境导致的跳过报成"护栏被破坏了"）。

## 7. 设置项

「设置」页可改，改完即时生效（存在数据库里）：

| 项 | 默认 | 说明 |
|---|---|---|
| 下载目录 | `downloads\` | 想放 D 盘别处就改这里 |
| 并发任务数 | 2 | 同时下几个。调高会更容易被站点风控 |
| 每任务限速 | **不限速** | 「添加下载」页也能直接改 |
| 分片并发数 | 8 | 单个任务内部并行分片数，对 HLS/DASH 流提速明显 |
| 失败重试次数 | 2 | |
| 按站点/作者建子目录 | 开 | |
| 读取浏览器登录态 | **不用** | 必须显式开启，不会偷读 |
| cookies.txt 文件 | 空 | 优先级高于浏览器；Netscape 格式 |

> ⚠️ 未知的设置键会**返回 400 报错**，而不是静默忽略。
> 这是刻意的：字段名拼错一个字母却显示"已保存 ✓"，比报错难查得多。

### 关于下载速度

- **限速是最大的变量。** 早期版本默认 5 MB/s，下大文件时它成了唯一瓶颈。
  现在默认不限速。
- **各站速度差异极大。** YouTube 通常能跑满带宽；B 站经常把单连接限到
  0.1~0.5 MB/s（站点侧限速，不是本工具造成的）。

### 关于进度条

一次下载要下**两条流**（视频流 + 音频流），yt-dlp 是**先后**下的，
所以进度条会：`0→100%`（视频流）→ **归零** → `0→100%`（音频流）→ 合并。

**归零不是 bug**，界面会显示「下载中（第 2 条流）」。

## 8. 命令行工具

npm start                          # 启动服务

### `tools/rebuild-library.js` —— 库万一丢了的救命工具

它扫磁盘上的视频文件（命名规则本身带信息）+ ffprobe + 封面时间戳，把记录重建回来。
**默认是预演，不加 `--yes` 不会写库。**

无法恢复的：原始 URL、发布时间、简介。文件本身完好，不影响播放与搜索。
重新粘一次原始链接就能把 URL 和简介补回来（文件已存在会跳过下载）。

指定端口 / 只监听本机：
```powershell
$env:VAULT_PORT=8899; npm start
```
